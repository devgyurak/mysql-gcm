<Aside type="caution" title="감사 전">
0.1.0 이 첫 릴리스이고, 이 구성은 사람의 암호 감사를 받지 않았습니다. 기대기 전에
[운영 제약](ops-constraints/)을 먼저 읽으세요.
</Aside>

```sql
SET @k = UNHEX('000102030405060708090a0b0c0d0e0f101112131415161718191a1b1c1d1e1f');  -- 공개 fixture 키

INSERT INTO patients (name_enc) VALUES (gcm_encrypt('홍길동', @k)), (gcm_encrypt('김철수', @k));

SELECT id, gcm_decrypt(name_enc, @k) AS name FROM patients
 WHERE gcm_decrypt(name_enc, @k) LIKE '%길%';     -- 1행, 홍길동 — 서버 안에서 일치
```

<CardGrid>
  <Card title="검색은 서버 안에서" icon="magnifier">
    `gcm_decrypt` 가 `utf8mb4` 를 돌려주므로 `LIKE '%길%'` 가 MySQL 자신의 collation 을 씁니다.
    걸러내려고 평문을 데이터베이스 밖으로 꺼낼 필요가 없습니다.
  </Card>
  <Card title="암호화만이 아니라 인증까지" icon="approve-check">
    모든 값에 128비트 GCM 태그가 붙습니다. 한 바이트라도 바뀌면 틀린 데이터가 아니라 오류가 납니다.
    키 길이로 AES-256 · 192 · 128 을 고르며, 256 미만은 기본적으로 꺼져 있습니다.
  </Card>
  <Card title="조인이 필요할 땐 결정적으로" icon="puzzle">
    `gcm_encrypt_det` 은 한 키 아래 같은 입력에 같은 값을 냅니다. 조인 키, `UNIQUE`, 정확일치용이며,
    같은지가 드러나므로 자유 텍스트에는 쓰지 않습니다.
  </Card>
  <Card title="측정했고, 한계도 적었습니다" icon="document">
    암호화된 30만 행에 대한 서버측 `LIKE` 가 CI 9회에서 `AES_DECRYPT` 의 0.75~0.96배였습니다.
    [어떻게 쟀고 무엇은 보여 주지 않는지](performance/).
  </Card>
</CardGrid>
